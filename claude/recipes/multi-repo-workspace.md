# Multi-repo workspace setup

Pattern for working on multiple sibling repos under one GitHub org while
keeping a dedicated, git-managed agent-config repo. Solves: surfacing
sibling repo notes (`AGENTS.md` / `CLAUDE.md`) when cwd is the config
repo, and granting file-access to siblings under both Claude Code and
Codex CLI.

The workspace repo is named `agents/` (not `claude/`) because it serves
both agents from one source of truth.

## Layout

```
~/work/{org}/
├── agents/                            ← cwd, the config repo
│   ├── AGENTS.base.md                 ← committed: hand-edited org notes
│   ├── AGENTS.md                      ← gitignored: generated (base + inlined siblings)
│   ├── CLAUDE.md                      ← gitignored: symlink → AGENTS.md
│   ├── .claude/
│   │   ├── settings.json              ← committed; siblings synced into additionalDirectories
│   │   └── settings.local.json        (gitignored)
│   ├── .repos/                        ← gitignored: symlinks to siblings
│   │   ├── product-api -> ../../product-api
│   │   ├── product-web -> ../../product-web
│   │   └── infra -> ../../infra
│   ├── bin/
│   │   ├── sync                       ← refresh symlinks + AGENTS.md + settings + codex snippet
│   │   └── launch                     ← runs sync, then exec claude or codex
│   ├── codex-profile.toml.snippet     ← gitignored: paste into ~/.codex/config.toml
│   ├── .gitignore
│   └── README.md
├── product-api/
├── product-web/
└── infra/
```

The `{org}/{repo}` parent path layout is preserved — product repos stay
where they normally live, and `agents/` is just another sibling repo.

## Source of truth: `AGENTS.base.md`

Hand-edit this. `bin/sync` produces `AGENTS.md` by concatenating
`AGENTS.base.md` with each sibling's `AGENTS.md` (or `CLAUDE.md` as
fallback) inlined under a `# === <repo> ===` heading. Both Claude (via
the `CLAUDE.md` symlink) and Codex (via `AGENTS.md` directly) read the
same generated content — no agent-specific syntax in either source.

```markdown
# {Org} — agent workspace

Org-wide rules here. Sibling repos under ~/work/{org}/ are surfaced via
symlinks in .repos/ and their AGENTS.md (or CLAUDE.md) files are inlined
below by bin/sync.
```

## `agents/.gitignore`

```
.repos/
.claude/settings.local.json

# Generated by bin/sync (AGENTS.base.md is the source of truth)
AGENTS.md
CLAUDE.md
codex-profile.toml.snippet
```

## `agents/bin/sync`

```bash
#!/usr/bin/env bash
set -euo pipefail

cd "$(dirname "$0")/.."
workspace="$(pwd)"
parent="$(cd .. && pwd)"
self="$(basename "$workspace")"

mkdir -p .repos

# 1. Refresh symlinks: one per sibling git repo (excluding ourselves).
sibling_names=()
sibling_abs_paths=()
sibling_rel_paths=()
for dir in "$parent"/*/; do
  name="$(basename "$dir")"
  [[ "$name" == "$self" ]] && continue
  [[ -e "$dir/.git" ]] || continue

  ln -sfn "../../$name" ".repos/$name"
  sibling_names+=("$name")
  sibling_abs_paths+=("$parent/$name")
  sibling_rel_paths+=("../$name")
done

# Drop dead symlinks for repos that disappeared.
for link in .repos/*; do
  [[ -L "$link" && ! -e "$link" ]] && rm "$link"
done

# 2. Build AGENTS.md = AGENTS.base.md + inlined sibling agent docs.
[[ -f AGENTS.base.md ]] || { echo "AGENTS.base.md missing" >&2; exit 1; }

inlined_count=0
{
  cat AGENTS.base.md
  echo
  echo "<!-- BEGIN: inlined sibling agent docs (managed by bin/sync) -->"
  for name in "${sibling_names[@]}"; do
    src=""
    if [[ -f ".repos/$name/AGENTS.md" ]]; then
      src=".repos/$name/AGENTS.md"
    elif [[ -f ".repos/$name/CLAUDE.md" ]]; then
      src=".repos/$name/CLAUDE.md"
    fi
    [[ -z "$src" ]] && continue
    echo
    echo "# === $name ($(basename "$src")) ==="
    echo
    cat "$src"
    inlined_count=$((inlined_count + 1))
  done
  echo
  echo "<!-- END: inlined sibling agent docs -->"
} > AGENTS.md

# 3. CLAUDE.md → AGENTS.md (Claude Code reads CLAUDE.md, Codex reads AGENTS.md).
ln -sfn AGENTS.md CLAUDE.md

# 4. Sync sibling paths into .claude/settings.json (Claude file-access permission).
command -v jq >/dev/null || { echo "jq required" >&2; exit 1; }
settings=".claude/settings.json"
mkdir -p .claude
[[ -f "$settings" ]] || echo '{}' > "$settings"
if [[ ${#sibling_rel_paths[@]} -gt 0 ]]; then
  paths_json=$(printf '%s\n' "${sibling_rel_paths[@]}" | jq -R . | jq -s .)
else
  paths_json='[]'
fi
tmp="$(mktemp)"
jq --argjson paths "$paths_json" \
   '.permissions.additionalDirectories = $paths' "$settings" > "$tmp"
mv "$tmp" "$settings"

# 5. Emit a Codex profile snippet for the user to install in ~/.codex/config.toml.
# Codex sandboxes to cwd by default; writable_roots extends that to sibling repos.
profile_name="$self"
{
  echo "# Generated by $self/bin/sync. Append (or merge) into ~/.codex/config.toml."
  echo "# Then launch with: codex --profile $profile_name"
  echo
  echo "[profiles.$profile_name]"
  echo "sandbox_mode = \"workspace-write\""
  echo
  echo "[profiles.$profile_name.sandbox_workspace_write]"
  echo "writable_roots = ["
  for p in "${sibling_abs_paths[@]}"; do
    echo "  \"$p\","
  done
  echo "]"
} > codex-profile.toml.snippet

echo "Synced ${#sibling_names[@]} sibling(s); inlined $inlined_count agent doc(s)."
echo "Wrote: AGENTS.md, CLAUDE.md (symlink), $settings, codex-profile.toml.snippet"
```

## `agents/bin/launch`

```bash
#!/usr/bin/env bash
set -euo pipefail

here="$(cd "$(dirname "$0")/.." && pwd)"
cd "$here"

agent="${1:-claude}"
shift || true

./bin/sync

case "$agent" in
  claude)
    exec claude "$@"
    ;;
  codex)
    profile="$(basename "$here")"
    exec codex --profile "$profile" "$@"
    ;;
  *)
    echo "Unknown agent: $agent (expected: claude | codex)" >&2
    exit 1
    ;;
esac
```

Use `./bin/launch` (or `./bin/launch codex`) to refresh
symlinks/AGENTS.md/settings/snippet before starting an agent.
File-access permission for sibling repos is set via
`permissions.additionalDirectories` in `.claude/settings.json`
(committed), so it also applies when launching via the VS Code
extension or any other launcher that doesn't run `bin/launch` first.

## First-time Codex setup

Codex sandboxes to cwd by default. To grant write access to sibling
repos, install the generated profile snippet once:

```sh
./bin/sync                                # generates the snippet
cat codex-profile.toml.snippet >> ~/.codex/config.toml
```

Verify the TOML structure matches your installed Codex version (the
snippet assumes
`profiles.<name>.sandbox_workspace_write.writable_roots`). After
installing, `./bin/launch codex` invokes `codex --profile agents`. Re-run
the snippet install whenever you add or remove a sibling repo.

## Two things to verify on first use

1. **Does Grep search into symlinked dirs?** ripgrep doesn't follow
   symlinks by default. If Grep from `agents/` misses files inside
   `.repos/product-api/`, tell the agent to grep `../product-api/` (the
   real path) instead. The `additionalDirectories` setting (and Codex
   `writable_roots`) grants access to the real paths, so this works.
   Worth calling out in `AGENTS.base.md`.

2. **Does the Codex sandbox grant the writable roots you expect?** Run
   a write inside a sibling repo from a Codex session and confirm it
   isn't blocked. If it is, the TOML key path probably differs in your
   Codex version — adjust the emitter in `bin/sync` accordingly.

## Why inline instead of `@` import?

An earlier version of this recipe used `@./.repos/<name>/CLAUDE.md`
import lines in the workspace `CLAUDE.md`. That worked for Claude Code
but didn't help Codex (no `@` import syntax), and import resolution
through symlinks was load-bearing. Inlining the sibling docs into
`AGENTS.md` at sync time produces a single static file that both agents
read identically — at the cost of regenerating on each launch, which is
cheap.

## Note on CLAUDE.md preload from sibling repos

`additionalDirectories` only grants file access — it does NOT cause
sibling `CLAUDE.md` files to preload. The inlined-into-`AGENTS.md`
approach above sidesteps this. Alternative if you'd rather not inline:
set `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` in your shell, and
Claude Code will preload `CLAUDE.md` from any `additionalDirectories`
entry (Claude-only — Codex still needs the inline).
